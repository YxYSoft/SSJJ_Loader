get_load_handler 均为结构体方法。hook 装在 watcher 线程（非 DllMain，避开 loader lock），
先轮询 GetModuleHandleW(L"libcef.dll") 就绪再 GetProcAddress 拿导出挂 DetourAttach。

## 诊断改进：DLL 无 OutputDebugString 输出
用户反馈：模块列表能看到 TestLoaderHook.dll，但 DbgView 无任何输出。
根因可能是 DbgView 未开 Capture Global Win32（跨会话/权限）导致 OutputDebugString 被静默丢弃，
或 DetourIsHelperProcess() 误判导致 watcher 线程未启动。
修复：
- 新增文件日志 WriteLogFile -> %TEMP%\TestLoaderHook.log（UTF-8 追加，不依赖 DbgView）。
- Dbg() 同时走 OutputDebugStringW + 文件。
- DllMain 入口即打点：pid + helper 标志 + exe 路径（确认 DLL 真被加载、跑在哪个进程）。
- watcher 线程开头打共享内存映射名 + timeout。
离线测试验证：日志完整输出 DllMain attach / watcher start / login data received /
libcef hook installed / cookies applied / js injected；helper 进程(rundll32)正确不启动业务线程。
真机排查：跑游戏前删旧 log，跑完看 %TEMP%\TestLoaderHook.log：
  - 无 DllMain attach => DLL 实际没进游戏进程（注入链问题）
  - helper=1 在游戏 exe 上 => DetourIsHelperProcess 误判（watcher 不启动的 bug）
  - 有 watcher start 但 30s 内无 login data received => 共享内存名/PID 不匹配（loader 端没写进去）
  - 有 login data 但 libcef not loaded timeout => 游戏 libcef 在子进程，注入目标选错

## 根因修复：watcher 读不到共享内存（真机卡在 watcher start 无 login data received）
真机日志确认：MicroClient.exe(19880) DllMain attach + watcher start 都有，但永远没有
login data received。映射名 Local\TestLoader_Login_19880 与 PID 完全对得上。
根因：GameLaunch.cpp 的 WriteLoginToSharedMemory 创建命名 file mapping、写入数据后
立刻 UnmapViewOfFile + CloseHandle，导致**命名内核对象在最后一个句柄关闭时即被销毁**，
而此时游戏主线程还没 ResumeThread，watcher 还没开始轮询。等 watcher 去 OpenFileMapping 时
对象已不存在 -> 永远读不到。离线 P2 测试之前没抓出（只验模块加载未验数据读取）。
修复：WriteLoginToSharedMemory 返回映射句柄且不再立即关闭；LaunchGameWithLogin 在
ResumeThread 后把句柄交给 DeferredCloseMapping 后台线程延迟 5 秒关闭（足以让每 100ms
轮询的 watcher 读到，且不阻塞 UI）。
回归：test_p2_launch.cpp e2e 段新增基于 %TEMP%\TestLoaderHook.log 的断言
（login data received + 含目标 pid），P2 由 14 -> 16 passed，断言 yes/yes。
注意：GameLaunch.cpp 改的是 Test_Loader.exe 源码，皮肤 zip 编译期嵌入，
**用户必须在 VS 重新生成解决方案**才能让修复进入实际 Release\Test_Loader.exe。
