## 修复：URL 唤起"unhandled payload: login-2/"（用户实测反馈）
- **根因**：Windows 经协议注册表唤起时（cmd `start yxysoft://login-2` 与双击 `.url` 快捷方式两条路）都会在 URL 末尾补 `/`，payload 变成 `login-2/`，原严格全数字校验失败 → 走 unhandled 分支
- **修复1**（UrlProtocol.cpp `ParseProtocolUrl`）：PercentDecode 后 `while` 剥掉尾部所有 `/`
- **修复2**（CMainDlg.cpp `HandleProtocolPayload`）：① login- 前缀后取数字段遇非数字即止（容忍尾部杂字符，双保险）；② 原先只打日志，现按账号 id 在 gbl_Users 找 `m_nIndex` 匹配项并调用 `LoginIdx(列表索引)`（与右键菜单同一登录逻辑）；找不到账号时 MessageBox 提示
- 验证：单测 25/25 PASS（新增 5 个带斜杠用例）；全量构建 0 error；smoke test 3/3 PASS；测试注册表键/桌面残留已清理
- 待用户：VS2022 重新构建 Release|Win32 → **先完全退出旧实例** → 首跑自动重注册协议 → 再试 `start yxysoft://login-<id>` 或双击桌面快捷方式（现在会真正执行登录：写 cookie + 启动游戏）
- 教训：协议 URL 的 payload 永远要按"唤起方会追加 `/`"来设计容错（cmd start / .url / 部分浏览器均如此）
