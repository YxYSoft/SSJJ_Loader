# 2026-10-16 区服选择 UI 重构（CAddUserDlg 统一添加/编辑）

## 背景
用户把"新增台服账号"菜单移除，统一集成进"添加账号"（CAddUserDlg 的 combobox 选 台服/4399 及具体区服）。
exe 已切 x64 可跑注入登录。

## 关键改动
- **区服表改为 C++ 唯一数据源**：`CAddUserDlg::kZones[]`（name/ntype/sid），含双线七区(sid=21)，不再依赖 XML 列表项。
  - sid 取自 `version.cpp` 权威表，与 DLL `Get4399ServerObj` 对齐。
  - `OnInitDialog` 用 `Active()`+`UnActive()` 强制加载 `m_pShowListView`（框架懒加载，否则 OnInitDialog 时空操作），再 `RemoveAll()`+`InsertChild()` 填充。
- **抓取无密码账号编辑**：`SetEditMode(true,bNoPassword,...)`，OnInitDialog 跳过台服项 + `SetEnabled(false)` 禁用账号/密码框（仅能改区服）。
- **HandleMenuAddByPwd（统一添加）**：按 `GetSelectedNtype()` 分支——100=纯存台服(不联网)；0=4399联网登录并写 `user.m_serverId=sid`。
- **HandleMenuEditPwd（编辑）**：`bNoPassword` 时无密码→仅改 serverid(不联网)；否则 台服(纯存)/4399(联网刷新+写 serverid) 分支。
- **删除死代码** `HandleMenuAddTwAccount`（菜单项已移除，分发 282-283 已注释）。

## DUIThink combobox 关键坑（重要）
- `CDUIComboxCtrl` 的 `m_pShowListView` **懒加载**：仅在首次展开下拉（`Active()`）时创建；`OnInitDialog` 直接 `RemoveAll/InsertChild` 是空操作。
- 可用 API：`RemoveAll()`/`InsertChild(CMMString)`/`GetCurSel()`/`SelectItem(int)`/`Active()`/`UnActive()`。
- `UnInit()` 内 `Close()` 销毁弹出窗口 HWND，故 `Active()` 后 `UnActive()` 不影响后续正常展开下拉（无可见闪烁，同步栈内完成）。
- `GetSelectedNtype/Sid` 双保险：优先 `GetCurSel()`→`m_vecVisible`→`kZones`；兜底按 `GetText()` 文本查表（应对视图未成功加载仍显示 XML 项）。
- `CMMString` 可隐式从 `const wchar_t*` 构造（`CMMString(_T("..."))` 用法已证实），故 `CMMString(L"台服壹区")` 直接可用。

## 未改（已确认正确）

- DLL `Get4399ServerObj`：与 version.cpp 对齐。

## CAddUserDlg 区服下拉两处 UI 修正（2026-10-16）

### 需求1：编辑时预显示原区服
- 根因：下拉项实际来自 ViewCombobox_Server.xml（与 kZones[] 同序、23 项），框架懒加载 m_pShowListView（仅展开时由 Active() 创建），
  故 OnInitDialog 里原 Active/UnActive/RemoveAll/InsertChild/SelectItem 全是空操作——预选永远不生效，仅靠 GetSelectedNtype/Sid 文本兜底保正确。
- 改法：删无效块；OnInitDialog 按 (m_nInitType,m_nInitSid) 算 m_nInitSel（kZones 索引，新增模式默认 1=4399默认，无密码编辑回落到 4399默认）
  后 SetText(kZones[m_nInitSel].name) 显示折叠框；新增消息映射 Dui_On_Notify_Ctrl(DuiNotify_ComboxExpand, IDC_ComboxCtrl_100153, OnComboxExpand)，
  展开回调 SelectItem(m_nInitSel) 预高亮。文件 CAddUserDlg.cpp/.h（新增成员 int m_nInitSel=1；m_vecVisible 现在恒空，选值走文本兜底）。

### 需求2：下拉选项文本居中
- 根因：列表项各自带 TextStyle=2906654212（0x8025 = DT_CENTER|DT_VCENTER|DT_SINGLELINE|DT_END_ELLIPSIS，本应居中），
  但列表视图克隆模板项时该项样式丢失，回退到列表视图默认左对齐（ViewCombobox_Server.xml 的 CDUIListViewCtrl 未设 ItemTextStyle*）。折叠框自身样式已居中，无问题。
- 改法：在 ViewCombobox_Server.xml 的 CDUIListViewCtrl 补 5 个属性，全部只读引用已居中的 2906654212：
  ItemTextStyleNormal/Hot/SelNormal/SelHot/Disabled（NameID 1909138281/1733426185/3790068587/2954905243/2549170266）；
  不影响其他共用 2906654212 的控件。同时把陈旧 ItemModelInitCount 由 22 修正为 23。

## CMainDlg 4399(账号密码)账号编辑「改不了区」根因修复（2026-10-16）

- 真因：`HandleMenuEditPwd` 的 4399 编辑分支用 `UserInfo{ username,password,cookie,detal,0,0 }`（6 参构造第6参是 m_nIndex）把主键写成 0；
  `DBWork::UpdateUser` 是 `UPDATE user ... WHERE id=m_nIndex`，于是 UPDATE 永远命中不到真实账号行，区服（及任何）改动被静默丢弃。
  这才是「账号密码账号改不了区」的核心 bug，与重登成不成功无关（重登成功也白改）。
- 改法（CMainDlg.cpp 596 else 分支重写）：
  1) 提交前抓取真实 `m_nIndex/m_username/m_password/m_token/m_detal`，构造 UserInfo 时带入 `m_nIndex`；
  2) 密码未变则不联网重登（离线也能改区），密码变了才重登刷新 cookie；
  3) 重登失败也兜底写回区服（沿用原账号信息），不再整条丢弃。
- 注意：原分支在 lambda 内访问 `gbl_Users[nSel]`，新代码改为捕获副本，去掉对 gbl_Users 的线程内访问，避免竞态。
- UserInfo 6 参构造顺序固定为 (username,password,token,detal,nType,nIndex)；聚合初始化不要漏 nIndex 否则 id=0。

  顺带去掉原托盘 `[台]` 特例，改为统一 `[台服]` 前缀。
